# Комплект для быстрых статических сайтов на Astro

Выжимка из нашего пайплайна разработки, урезанная до одного сценария: **на входе картинка макета, на выходе статический сайт на сервере**. Всё, что не работает на этом сценарии, выброшено намеренно - см. «Чего здесь нет».

Рассчитан на работу через ИИ-агента с доступом к файлам и командам (Codex, Claude Code и подобные). Агент читает эти файлы сам, человеку достаточно README.

## Порядок работы

1. **Заполнить [PROJECT.md](PROJECT.md)** - один файл на сайт: домен, команда сборки, куда выкладывается, палитра и шрифты с макета. Все остальные шаги читают его. Не заполнен - дальше не идём, иначе проверяющие сверяют результат непонятно с чем.
2. **[01-maket.md](01-maket.md)** - прочитать макет до первой строки кода: сетка, отступы, цвета пипеткой, шрифты. Самая частая причина «похоже, но не то» - код начали писать раньше, чем разобрали картинку.
3. Свёрстать страницу. Это делает сам агент, инструкций здесь нет - он это умеет.
4. **[02-proverka.md](02-proverka.md)** - контур проверки: сначала машинные проверки, потом четыре проверяющих по настоящим скриншотам.
5. **[03-vykat.md](03-vykat.md)** - заливка на сервер и проверка на живом адресе.

Маршрут работы (что из этого можно пропустить и когда) - [00-marshrut.md](00-marshrut.md).

## Два правила, на которых всё держится

**Результат без доказательства не считается сделанным.** Не «страницу собрал», а «вот команда сборки, вот её вывод без ошибок, вот три скриншота». Проверяющий смотрит скриншот живой страницы, а не разметку: разметка показывает намерение, скриншот - результат.

**Проверяет не тот, кто делал.** Тот, кто верстал, видит на странице свой замысел, а не то, что там нарисовано. Поэтому проверки в `roles/` запускаются отдельными заходами, с чистого листа: в новом окне чата или отдельной задачей агента, где на входе только скриншот и промпт роли, без истории вёрстки.

## Чего здесь нет и почему

| Выброшено | Почему |
|---|---|
| Спеки, архитектура, разбиение на задачи | Макет уже есть, он и есть спека. Согласовывать нечего |
| Цикл копирайтинга из пяти проверяющих | Текст берётся с макета дословно, а не сочиняется |
| Тесты и тестовая стратегия | В статике нет логики, которую можно сломать незаметно. Её ломает вёрстка, а вёрстку ловят скриншоты |
| База знаний проекта | Заменена одним файлом `PROJECT.md` |
| Проверка на соответствие дизайн-системе | Дизайн-системы нет, источник правды - макет. Заменена сверкой с картинкой (`roles/01-maket.md`) |
| Аудит безопасности | Статика без форм и данных. Появилась форма с приёмом заявок - это уже не «просто статика», см. `00-marshrut.md` |
