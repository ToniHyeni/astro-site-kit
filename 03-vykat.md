# Выкат на сервер и проверка на живом адресе

## До первой заливки

Один раз на проект, до того как что-то поедет на сервер, записать в `PROJECT.md`:

- адрес сервера и как на него заходим;
- **точная папка**, куда кладётся сайт;
- что ещё лежит на этом сервере рядом. Если там другие сайты - это меняет команду заливки;
- чем откатываемся: копия предыдущей версии или git.

Последний пункт обязателен. Заливка без возможности вернуть предыдущую версию - необратимое действие, а необратимое делается только с разрешения владельца.

## Заливка

```bash
# папка сайта на сервере отдельная, ничего чужого рядом нет
rsync -avz --delete dist/ user@server:/var/www/site/

# на сервере есть другие сайты: заливаем добавлением, без --delete
rsync -avz dist/ user@server:/var/www/site/
```

Разница между этими двумя строками - целые чужие сайты. Флаг удаления ставится только когда точно известно, что папка принадлежит одному этому сайту и ничего вручную туда не клали.

Первая заливка на новый сервер делается **сначала без изменений**: скопировать, посмотреть список файлов, убедиться, что попало туда, куда задумано. Пробный прогон:

```bash
rsync -avzn --delete dist/ user@server:/var/www/site/   # ничего не меняет, только показывает
```

## Проверка после выката

Выложили - проверяем на живом адресе, а не на превью. Это отдельный шаг, и его пропускают чаще всего: на сборке страница была живая, а на сервере отдаёт 404, потому что папка не та.

**Шаг 1. Убедиться, что на сервере новая версия.** Открыть адрес и найти на странице то, что появилось в этой правке. Проверять старую версию и радоваться результату - классическая ошибка.

```bash
curl -sI https://домен/страница | head -3        # 200, а не 404 и не 301 в никуда
curl -s https://домен/страница | grep -c "новый текст со страницы"
```

**Шаг 2. Пройти короткий список.** Всё машинно, минуты три:

```bash
curl -sI https://домен | head -1                          # главная отвечает 200
curl -s https://домен/страница | grep -o '<title>[^<]*'   # заголовок вкладки на месте
curl -sI https://домен/robots.txt | head -1               # robots отдаётся
curl -s https://домен/sitemap-index.xml | head -5         # карта сайта на месте
```

- сайт открывается по **https**, замок в браузере без предупреждений;
- **все ссылки в меню и подвале ведут куда надо** - проверяются на живом адресе, а не в исходниках: путь, который работал локально, на сервере может смотреть не туда;
- **картинки грузятся** - не остались ссылками на локальные файлы;
- **на телефоне не разъехалось.** Снять скриншот живого адреса: `./scripts/shots.sh https://домен`;
- **форма отправляет заявку и она доходит.** Если формы нет - пропускаем, если есть - проверяем настоящей отправкой.

**Шаг 3. Записать результат.** Три строки: что проверил, чем, что получил. Это и есть доказательство выката.

## Если сломалось

Сначала вернуть предыдущую версию, потом разбираться. Сайт лежит - это не время читать логи и искать причину: заливаем обратно последнюю рабочую копию, убеждаемся, что открылась, и только после этого ищем, что пошло не так.

Чинить прямо на сервере правкой файлов - последнее средство и только под запись: такая правка теряется при следующей заливке, и поломка возвращается.
